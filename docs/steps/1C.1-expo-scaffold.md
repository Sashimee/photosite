# Step 1C.1 – Expo app scaffold

Plan reference: `docs/PLAN.md` step 1C.1. Owner: mobile-developer. Branch: `feat/1C.1-expo-scaffold`. Blocked by 0.10 and 0.11 (merged).

## Goal

`apps/mobile` is a running Expo app (managed workflow, expo-router) with NativeWind, i18next reading the shared ICU catalogs, a secure-storage session helper, the typed API client against the mock, Sentry wired as a no-op without DSN, and EAS configuration prepared.

## Workarounds for missing human input

- Apple Developer / Google Play accounts and an Expo account (0.6) do not exist: write `eas.json` (development, preview, production profiles) and `app.config.ts` with bundle id `lu.photoo.app` / package `lu.photoo.app`, but do not run `eas init` or any command that needs login. `extra.eas.projectId` is read from `EAS_PROJECT_ID` and omitted when unset. Record in `docs/steps/human-followups.md`: create the Expo project, set `EAS_PROJECT_ID`, then run the first dev builds.
- No brand kit (O5): neutral NativeWind theme mirroring `apps/web/src/styles/tokens.css` values, placeholder icon/splash generated as plain coloured PNGs, listed in human-followups.
- No Sentry DSN: `@sentry/react-native` initialised only when `EXPO_PUBLIC_SENTRY_DSN` is set.

## Tasks

1. Replace the placeholder with the current Expo SDK (57.x) template dependencies at the versions `npx expo install` resolves for that SDK, pinned exactly; React Native per the SDK. Scripts: `start`, `ios`, `android`, `web` (dev only), `lint`, `typecheck`, `test`; no `build` script (turbo must skip it) since native builds go through EAS.
2. pnpm monorepo compatibility: Metro config for workspaces (watchFolders, `node-linker` concerns); verify `@photoo/shared`, `@photoo/i18n`, `@photoo/api-client` resolve in Metro. If pnpm's isolated linker breaks Metro, document the minimal fix (e.g. `.npmrc` public-hoist patterns scoped to mobile) and explain it.
3. expo-router: `app/_layout.tsx` with providers, tabs placeholder (Discover, Requests, Messages, Account), `+not-found`.
4. i18n: i18next + ICU plugin loading `@photoo/i18n` catalogs, device locale via `expo-localization` resolved with `resolveLocale` from `@photoo/shared`; strings under `mobile.*` in `en.json`; `pnpm i18n:check` green.
5. NativeWind 4 + Tailwind config with the neutral tokens.
6. `src/lib/session.ts`: get/set/clear bearer token in `expo-secure-store` only; `src/lib/api.ts`: `createApiClient` with `EXPO_PUBLIC_API_URL` validated with zod and an auth middleware adding the bearer token.
7. `app.config.ts`: name, slug, scheme `photoo`, bundle ids, iOS `usesAppleSignIn` false for now (1C.2), privacy manifest placeholder entries for the APIs used, Android permissions minimal (none beyond defaults).
8. Tests: jest-expo or Vitest (whichever the Expo SDK supports for RN component tests; report the choice) for the session helper, API client header injection, locale resolution, and a render test of the tab layout.
9. Verify: `pnpm --filter @photoo/mobile start --web` renders the tabs in a browser (smoke via curl or expo export for web), `npx expo-doctor` passes or its findings are reported, `npx expo export --platform ios --platform android` bundles without errors (no native build needed).
10. Update `CLAUDE.md` Commands and `docs/steps/human-followups.md`.

## Out of scope

Auth screens (1C.2), push (1C.5), analytics consent (1C.8), store assets (1C.9).

## Done when

- All root checks + audit green, `expo export` succeeds for iOS and Android, CI green, PR merged
