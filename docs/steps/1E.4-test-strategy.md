# Step 1E.4 – Test strategy and CI integration tests

Plan reference: `docs/PLAN.md` step 1E.4. Owner: test-writer, with devops-engineer for the CI workflow. Branch: `feat/1E.4-test-strategy`.

## Problem

Integration tests in `packages/db` and `apps/api` skip in CI because CI has no Postgres or Redis. Database behaviour (migrations, constraints, seed, auth flows) is only verified on developer machines. No coverage thresholds exist.

## Tasks

1. CI services (devops-engineer): add `postgis/postgis:16-3.5` and `redis:7-alpine` service containers to `.github/workflows/ci.yml` with health checks. Create `photoo_test` and `photoo_shadow`, apply migrations with `prisma migrate deploy` before tests, and set `TEST_DATABASE_URL`, `REDIS_URL` and the api test env (dev-only secrets, never real ones). Image tags must match `infra/docker/compose.dev.yml`.
2. Make the skip impossible in CI: when `CI=true`, the env-gated integration suites fail instead of skipping if their variables are missing (a shared helper in each package, tested).
3. Test database hygiene: a documented convention (unique data per test, cleanup of own rows, `fileParallelism: false` where one database is shared) in `docs/ARCHITECTURE.md` testing section; check that the existing db and api suites follow it.
4. Coverage: Vitest v8 coverage for `packages/shared`, `packages/i18n`, `packages/db`, `apps/api`, `apps/web`; jest coverage for `apps/mobile`. Thresholds set just below current measured values (report them) so they only ratchet up; CI fails below threshold. Generated contract files and Prisma client excluded.
5. Root script `pnpm test:integration` that brings nothing up itself but runs the gated suites with the local stack env; documented in `CLAUDE.md`.
6. Playwright (1B.12) and Maestro (1C.10) remain in their own steps; note the plan in the testing section.

## Done when

- CI runs db and api integration tests against real Postgres and Redis (visible in the job log, zero skipped)
- Coverage thresholds enforced; all checks + audit green; PR merged
