## Decisions for this step

- **One read-only endpoint, `GET /v1/admin/dashboard?window=7d|30d|90d`** (default `30d`). Counts are for `createdAt` (or `occurredAt` for ledger rows) inside `[now − window, now)`, plus the same figure for the previous window of equal length so the UI can show a delta without a second request. Backlogs are point-in-time and have no window.
- **Any admin permission can call it; money needs `finance`.** The endpoint requires at least one grant (same guard as `/admin/me`). The `money` section is `null` unless the caller holds `finance` (or `superadmin`), so GMV and fee revenue never reach a moderator. The UI shows "requires finance permission" in place of the money cards; it never infers the figures.
- **KPIs:**
  - sign-ups per role: users created in window, by `UserRole` (`client`, `photographer`, `professional`); a user with two roles counts in both, and the total is distinct users. `admin` is excluded. Soft-deleted / GDPR-erased users are still counted for the window they signed up in (the row exists); this is a sign-up count, not an active-user count.
  - requests created, quotes sent, bookings created (status ≠ `pending_payment` and ≠ `cancelled` before payment, i.e. bookings that were paid).
  - money, per currency (never summed across currencies): GMV = sum of `charge` ledger entries; refunds = sum of `refund` entries; fee revenue = sum of `platform_fee` entries (written at release, so this is realised fee, labelled as such).
  - backlogs: verification cases `submitted` + `in_review`, provenance checks awaiting review, open reports, open data requests. Each card links to its queue.
- **Aggregates only, no personal data in the response.** No ids, names or emails. Counts are computed in SQL (`count`/`groupBy`/`aggregate`), never by loading rows.
- **No caching layer in this step.** The queries hit indexed columns; if they get slow later, add a materialised view, not an in-process cache (see the #193 note on `PlatformSettingsService`).
- **Not audited.** It is a read with no personal data; reads of aggregates do not write `AuditLog`.
- **Admin is en-only;** strings under `admin.dashboard.*`. Money uses `formatCents` from `apps/admin/src/lib/money.ts`.

## Tasks

1. Contract (`packages/shared/src/contract/admin.ts`): `AdminDashboardQuerySchema`, `AdminDashboardSchema` (`window`, `generatedAt`, `signups`, `activity`, `money | null`, `backlogs`; each windowed metric `{ current, previous }`; money as arrays of `{ currency, current, previous }` in cents). Regenerate `openapi.json` and the api-client.
2. API (`apps/api/src/modules/admin/`): `admin-dashboard.controller.ts`, `.service.ts`, `.repository.ts`; any-grant guard; `money` gated on `finance`/`superadmin`; Prisma aggregates only.
3. Admin web: replace the placeholder `app/(admin)/page.tsx` with the dashboard — window switcher (search param), KPI cards with delta, money cards or the permission notice, backlog cards linking to their queues (only to queues the caller can open).
4. i18n `admin.dashboard.*` (en).
5. Tests:
   - API service unit tests: window boundaries (inclusive start, exclusive end), previous-window maths, multi-role user counted once in total, `money` null without `finance`, per-currency separation, empty database returns zeros not nulls.
   - API integration test against the stack: seeded rows land in the right window and buckets; a moderation-only admin gets `money: null`; a user without grants gets 403.
   - Admin: renders every card, delta sign and zero-previous case, money hidden with the notice, backlog links hidden for queues without permission, invalid `window` param falls back to `30d`.

## Out of scope

Charts/time series, CSV export, per-country breakdown, conversion funnels (Phase 2+; file as issues if wanted).
