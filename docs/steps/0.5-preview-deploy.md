## Decisions for this step

- **One host, path routing.** Traefik (managed by Dokploy) sends `footoo.bas.lu/v1/*` and the API's excluded non-prefixed routes that need to be public (auth callbacks, if any) to `api`, and everything else to `web`.
  - The API's global prefix is already `/v1`, so no prefix stripping is needed.
  - `NEXT_PUBLIC_API_URL=https://footoo.bas.lu`. Web and API are then same-origin: the session cookie needs no cross-site settings and `WEB_ORIGINS` is just `https://footoo.bas.lu`.
  - Health endpoints stay internal (container healthchecks), not routed.
- **Images.**
  - Multi-stage Dockerfiles for `api`, `worker` and `web`: Node 24 alpine or slim, pnpm with `turbo prune --docker`, non-root user, `NODE_ENV=production`, `HEALTHCHECK`, no dev dependencies or source maps with secrets in the final image.
  - `web` uses Next.js `output: 'standalone'`.
  - A one-shot `migrate` target runs `prisma migrate deploy` before `api` starts. It never uses `migrate dev` or reset.
- **Build and deploy.**
  - GitHub Actions workflow `deploy-preview.yml`, triggered on push to `main` and after the CI workflow succeeds on `main`.
  - It builds and pushes `ghcr.io/sashimee/photosite-{api,worker,web}:main` and `:sha-<short>` with the built-in `GITHUB_TOKEN`, then calls the Dokploy deploy webhook from the `DOKPLOY_PREVIEW_WEBHOOK_URL` secret.
  - A missing secret fails the deploy job loudly, not silently.
  - `NEXT_PUBLIC_*` values are baked into the web image at build time, so the workflow passes them as build args from repository variables, never secrets.
- **Dokploy compose.** `infra/dokploy/preview/compose.yml` (the `infra/dokploy/` layout from ARCHITECTURE) defines:
  - `web`, `api`, `worker` and `migrate` from GHCR;
  - `postgres` (postgis/postgis:16), `redis:7` and `minio` for S3 until a real EU bucket exists;
  - `clamav`, if memory allows on the VPS, otherwise uploads stay in pending scan and this is recorded;
  - named volumes and Traefik labels for `footoo.bas.lu` with Let's Encrypt;
  - no ports published on the host except through Traefik;
  - a `.env.example` listing every variable with no values.
  - Email on the preview goes to a Mailpit container that isn't exposed publicly, until Brevo exists (0.6). Sign-up verification links can be read through an SSH tunnel or a Dokploy terminal.
- **Seed.** The preview gets the demo seed so the site has content. The seed refuses `NODE_ENV=production`, so the one-shot `seed` compose service (profile `seed`, run manually) sets `NODE_ENV=development`; the long-lived services stay on production. The real prod project never defines that service.
- **Known preview limits.** Verification email isn't delivered until 1A.7 adds the worker email processor over SMTP (Mailpit on the preview, Brevo later); demo seed users can sign in meanwhile. Browser uploads need a public S3 host (`s3.footoo.bas.lu`, human follow-up). Public images are served through a GET-only Traefik route to MinIO at `/photoo-public/`. `TRUSTED_PROXIES` defaults to the private ranges so per-IP limits see real clients (#19).
- **Noindex, three layers.** They're controlled by `NEXT_PUBLIC_ALLOW_INDEXING`, which defaults to off, so any environment that forgets it stays hidden:
  1. `robots.txt` via `app/robots.ts` returns `Disallow: /` when indexing is off.
  2. Root metadata sets `robots: { index: false, follow: false }`.
  3. `X-Robots-Tag: noindex, nofollow` is sent from both the `next.config.ts` headers and the API (Fastify hook or a Traefik middleware label).
- **Merging to main.** Per Alex, `dev` merges into `main` as soon as the preview is usable (at least browsing the web shell and sign-up/sign-in against the real API). Each dev→main merge uses a PR with green CI.

## 0.5a tasks

1. **devops-engineer:**
   - Dockerfiles in `apps/api`, `apps/worker` and `apps/web` (or `infra/docker/<app>.Dockerfile`, matching repo convention), plus `.dockerignore`.
   - Verify with `docker build` locally for all three.
   - Run the built images against the local stack (`pnpm stack:up`): `api` answers its health route, `web` renders `/en`, and `worker` connects to Redis.
2. **devops-engineer:** `infra/dokploy/preview/compose.yml` and `.env.example`, with the Traefik labels above. Validate it with `docker compose config`.
3. **devops-engineer:** `.github/workflows/deploy-preview.yml`, with actions pinned by SHA as in `ci.yml`, `permissions: packages: write` scoped to the job, and concurrency cancelling older deploys.
4. **web-developer:** the noindex layers and `NEXT_PUBLIC_ALLOW_INDEXING` in `apps/web/src/lib/env`, `.env.example` and tests (robots output and meta for both values). **api-developer** or devops-engineer adds `X-Robots-Tag` on API responses.
5. **devops-engineer:** runbook `infra/dokploy/preview/README.md` with the exact Dokploy UI steps Alex performs (see follow-ups), how to read logs, how to roll back to a `sha-` tag, and how to run the seed.
6. **docs-sync:** update `docs/DECISIONS.md` (D9 host is `dok.seil.pro`, preview domain `footoo.bas.lu`), `docs/ARCHITECTURE.md` runtime topology, and the `CLAUDE.md` commands.
7. **Checks:** all root checks, `docker build` of the three images, and `docker compose -f infra/dokploy/preview/compose.yml config`.
8. **Security checkpoint** (security-reviewer, short): the image runs as non-root, no secrets in layers or build args, only Traefik is exposed, noindex is in place, and the Postgres/Redis/MinIO ports aren't published.
