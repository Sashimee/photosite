# Step 1E.9 – Browser smoke test in CI

New step in lane E, owner test-writer with devops-engineer for the workflow. Extends 1E.4 (test strategy) and comes **before** 1B.12, which plans full Playwright user flows once checkout and onboarding exist. This step is deliberately much smaller than 1B.12: it loads pages in a real browser and fails on a broken one.

## Why this exists

On 2026-09-18 the preview was broken for a visitor while every check was green. Three separate bugs, none of which any existing test could see:

| Bug | Why the suite missed it |
|---|---|
| `NEXT_PUBLIC_*` parsed from the whole `process.env` object, so every public value was `undefined` **in the browser** and the env module threw at evaluation (#171) | Server rendering has a real `process.env`; vitest has a real `process.env`; `next build` succeeds. It only fails in a browser. |
| Server-side fetches used the public hostname, so SSR traffic left the host and came back through Traefik's CrowdSec bouncer until the host's own IP was banned (#167) | Nothing in CI runs the container against a reverse proxy. |
| The session cookie is `__Secure-photoo_session` over https but the apps matched only `photoo_session`, so every signed-in page redirected back to sign-in (#167) | Local dev is http, so the bare name is correct there, and every test used it. |

The first is the important one: **`curl` returned HTTP 200 with correct HTML for a page that was visibly broken**, because the crash happened during hydration. Status-code checks cannot see that class of bug, and I spent hours reporting the preview healthy on that basis. One browser load would have shown it immediately.

## Decisions for this step

- **Scope is "does the page work", not "does the feature work".** For a chosen set of routes: load it in Chromium, and fail if there is any uncaught page error, any console error, any failed request for a same-origin resource, or the error boundary's text in the rendered output. No assertions about content — 1B.12 owns flows.
- **`innerText`, never `textContent` or the HTML.** The error-boundary string also lives in the RSC payload inside a `<script>`, so matching the HTML gives a false positive on a perfectly good page (which cost real time on 2026-09-18) and matching only the status code gives a false negative. The check looks at what a human would read.
- **Console errors fail the run.** That is what would have caught #171: the browser logged `Invalid environment configuration: NEXT_PUBLIC_API_URL: expected string, received undefined` while the page still returned 200. An allow-list exists for known-noisy third-party messages and starts **empty**; every entry needs a comment naming why.
- **Every locale is covered, not just `en`.** A visitor in Luxembourg lands on `/fr` or `/de`. Testing one locale is how a locale-specific break ships.
- **Signed-out and signed-in.** The signed-in pass uses the seeded client, so a cookie-name or session bug fails the run. This is the check that would have caught the `__Secure-` prefix.
- **It runs against the built app in CI, not against the preview.** A test that depends on the deployed environment fails for reasons that are not the commit's fault, and cannot block a bad merge. `next start` plus the API and its stack in service containers, seeded exactly as the integration suites already do.
- **A second, separate job checks the deployed preview after `Deploy preview` finishes**, and reports without blocking: same script, `BASE_URL` pointed at `footoo.bas.lu`. It is the only way to catch an environment-shaped problem such as a banned IP or a missing env var in Dokploy, and it must be **rate-limited and serial** — the investigation on 2026-09-18 got the runner's own IP banned by CrowdSec for exactly this traffic shape.
- **Playwright is added at the repo root, configured once**, since 1B.12 and the mobile Maestro work will both need it. Browsers are installed with `--with-deps` and cached by version.
- **The route list lives in one file** next to the test, with a comment per entry saying why it is worth loading. Adding a page means adding a line.

## Routes for the first version

Signed out, for each of `en`, `fr`, `de`, `pt`, `es`: `/`, `/photographers`, `/photographers/{seeded-slug}`, `/sign-in`, `/legal/imprint`, `/legal/privacy`. Signed in as the seeded client, in `en` only: `/requests`, `/quotes`, `/messages`, `/account`.

That is 30 signed-out loads and 4 signed-in ones — a couple of minutes, and it would have caught all three of the bugs above.

## Tasks

1. Root Playwright config, a `smoke` project, and the browser install/cache step in `ci.yml`.
2. `tests/smoke/pages.ts` (the route list) and `tests/smoke/smoke.spec.ts` (the four failure conditions above).
3. A CI job that starts the stack, seeds it, builds and starts web and api, and runs the smoke project.
4. A separate post-deploy job in `deploy-preview.yml` that runs the same spec against the preview, serial and rate-limited, reporting without blocking.
5. `CLAUDE.md` Commands gains the local invocation.

## Out of scope

User flows (1B.12), visual regression, Lighthouse (1B.11 already owns Core Web Vitals), and mobile (1C.10).

## Human follow-ups

- If the post-deploy job's traffic trips CrowdSec again, its runner IP needs allowlisting on the host — the same mechanism that banned a workstation IP during the 2026-09-18 investigation. Keeping the job serial should avoid it; the fallback is an allowlist entry.
