# Step 1A.2 – API bootstrap and auth module

Plan reference: `docs/PLAN.md` step 1A.2 (effort L). Owner: api-developer; security-reviewer checkpoint afterwards (1E.6). Decision: D20 (Better Auth 1.7.5).

`apps/api` is still the empty placeholder from 0.1; no step created the NestJS application. Split into two PRs:

| Sub-step | Scope | Branch |
|----------|-------|--------|
| 1A.2a | NestJS + Fastify bootstrap, config, errors, validation from the shared contract, health, logging | `feat/1A.2a-api-bootstrap` |
| 1A.2b | Better Auth integration and every `/v1/auth/*` operation in the contract | `feat/1A.2b-auth` |

## 1A.2a tasks

1. NestJS 12 (latest stable) with `@nestjs/platform-fastify`, exact versions; scripts `dev` (watch), `build`, `start`, `lint`, `typecheck`, `test`. Module layout per the api-developer agent (`src/modules/<name>/…`).
2. Config: zod-validated env (`DATABASE_URL`, `REDIS_URL`, `PORT`, `PUBLIC_API_URL`, `WEB_ORIGINS`, `NODE_ENV`); the app refuses to start and names the invalid variable.
3. Prisma provider from `@photoo/db` `createPrismaClient`, closed on shutdown; Redis client provider.
4. Validation: a pipe or route helper that validates params/query/body with the zod schemas exported by `@photoo/shared` (the same objects registered in the OpenAPI registry), rejecting unknown keys with 400 and the `ApiError` shape.
5. Errors: a global exception filter that maps every error to `ApiError` (`code`, `message`, `details`, `requestId`), never leaks stack traces, and logs 5xx with the request id.
6. Request id (`x-request-id` in and out), pino logging with a redaction list (authorization, cookie, set-cookie, password, token, secret) per SECURITY.md.
7. Security basics: `@fastify/helmet`, CORS allow-list from `WEB_ORIGINS`, body size limit, `/v1` global prefix, graceful shutdown.
8. `GET /health` (liveness) and `GET /ready` (DB + Redis ping) outside `/v1`, added to the shared contract first and regenerated.
9. `GET /openapi.json` serves the document built by `buildOpenApiDocument()` from `@photoo/shared`; a test asserts every registered contract path either has a Nest route or is on an explicit "not yet implemented" list that shrinks each step (starts with everything except health/ready).
10. Tests: Fastify inject tests for health/ready, validation error shape, unknown key rejection, 404 shape, request id propagation, redaction.
11. `CLAUDE.md` Commands: `pnpm --filter @photoo/api dev`.

## 1A.2b tasks (planned, detailed when 1A.2a merges)

Better Auth mounted on Fastify under `/v1/auth`, Prisma adapter mapped to our models per the 1A.1 field mapping; resolve its open items (add `User.name` via schema-migrator, bridge `emailVerified` to `emailVerifiedAt`, hash `Verification.value`, encrypt `TwoFactor.secret`); session-token SHA-256 adapter wrapper with tests; Argon2id hash/verify; HIBP check; bearer plugin for mobile; TOTP; Redis rate limits and lockout; role selection at sign-up and add-role writing `AuditLog`; OAuth providers enabled only when their env credentials exist (0.6 pending); verification and reset emails queued to the worker (Mailpit locally). Contract responses must match `packages/shared` auth schemas exactly.
