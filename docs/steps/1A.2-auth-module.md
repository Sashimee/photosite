# Step 1A.2 – API bootstrap and auth module

Plan reference: `docs/PLAN.md` step 1A.2 (effort L). Owner: api-developer; security-reviewer checkpoint afterwards (1E.6). Decision: D20 (Better Auth 1.7.5).

`apps/api` is still the empty placeholder from 0.1; no step created the NestJS application. Split into two PRs:

| Sub-step | Scope | Branch |
|----------|-------|--------|
| 1A.2a | NestJS + Fastify bootstrap, config, errors, validation from the shared contract, health, logging | `feat/1A.2a-api-bootstrap` |
| 1A.2b | Better Auth integration and every `/v1/auth/*` operation in the contract | `feat/1A.2b-auth` |

## 1A.2a tasks

1. NestJS 12 (latest stable) with `@nestjs/platform-fastify`, exact versions; scripts `dev` (watch), `build`, `start`, `lint`, `typecheck`, `test`. Module layout per the api-developer agent (`src/modules/<name>/…`).
2. Config: zod-validated env (`DATABASE_URL`, `REDIS_URL`, `PORT`, `PUBLIC_API_URL`, `WEB_ORIGINS`, `NODE_ENV`); the app refuses to start and names the invalid variable.
3. Prisma provider from `@photoo/db` `createPrismaClient`, closed on shutdown; Redis client provider.
4. Validation: a pipe or route helper that validates params/query/body with the zod schemas exported by `@photoo/shared` (the same objects registered in the OpenAPI registry), rejecting unknown keys with 400 and the `ApiError` shape.
5. Errors: a global exception filter that maps every error to `ApiError` (`code`, `message`, `details`, `requestId`), never leaks stack traces, and logs 5xx with the request id.
6. Request id (`x-request-id` in and out), pino logging with a redaction list (authorization, cookie, set-cookie, password, token, secret) per SECURITY.md.
7. Security basics: `@fastify/helmet`, CORS allow-list from `WEB_ORIGINS`, body size limit, `/v1` global prefix, graceful shutdown.
8. `GET /health` (liveness) and `GET /ready` (DB + Redis ping) outside `/v1`, added to the shared contract first and regenerated.
9. `GET /openapi.json` serves the document built by `buildOpenApiDocument()` from `@photoo/shared`; a test asserts every registered contract path either has a Nest route or is on an explicit "not yet implemented" list that shrinks each step (starts with everything except health/ready).
10. Tests: Fastify inject tests for health/ready, validation error shape, unknown key rejection, 404 shape, request id propagation, redaction.
11. `CLAUDE.md` Commands: `pnpm --filter @photoo/api dev`.

## 1A.2b tasks

Owner: api-developer, with schema-migrator for the schema change in task 1. Afterwards the security-reviewer runs its checkpoint (1E.6) against SECURITY.md "Authentication and sessions".

1. Schema (schema-migrator, DATA-MODEL updated first): `User.name String?` (Better Auth requires a name; derived from the email local part at sign-up, editable later); `Verification.value` stored hashed; `TwoFactor.secret` and `backupCodes` encrypted at rest (AES-256-GCM with `AUTH_ENCRYPTION_KEY`, 32-byte base64, validated at startup). Migration via `migrate diff` + `migrate deploy`.
2. Better Auth 1.7.5 mounted under `/v1/auth` on Fastify (a catch-all route forwarding to `auth.handler`), with the Prisma adapter mapped to our models per the 1A.1 field mapping (`modelName`/`fields`), `advanced.database.generateId: false` so Prisma's uuid v7 default applies, `emailVerified` bridged to `emailVerifiedAt` with `databaseHooks`.
3. Session token hashing: an adapter wrapper hashing `session.token` (SHA-256) on create and in `where` clauses, mapped to `tokenHash`. Tests prove the raw token never reaches the database and lookups still work.
4. Passwords: Argon2id (`@node-rs/argon2`, as in the seed) via `emailAndPassword.password.hash/verify`; minimum 10 characters; `haveibeenpwned` plugin on sign-up and change (fail open with a logged warning when HIBP is unreachable, so an outage does not block sign-ups; decision recorded in DECISIONS).
5. Cookies for web (`photoo_session`, httpOnly, Secure outside development, SameSite=Lax); `bearer` plugin for mobile; sliding expiry; "log out everywhere" revokes all sessions. CSRF double-submit token for cookie-authenticated state changes (SECURITY.md web).
6. Contract adapter: `/v1/auth/*` requests and responses must match the zod schemas in `packages/shared/src/contract/auth.ts`, validated in tests with the shared schemas (not only Better Auth's own shapes). Where Better Auth's native route differs, add a thin Nest controller that calls `auth.api.*` and returns the contract shape. Remove the implemented operations from `not-yet-implemented.ts`.
7. Roles: sign-up requires roles (client/photographer/professional; admin never self-assignable); `POST /v1/auth/roles` adds a role and writes `AuditLog`. Admin sessions: 12 h lifetime, TOTP required before any admin route (guard for 1D).
8. TOTP: `two-factor` plugin enroll, verify, disable (disable needs password + code); backup codes; lockout after repeated failures.
9. Rate limits and lockout on Redis (`secondaryStorage`): sign-in, sign-up, password reset, TOTP, per IP and per account; 429 in `ApiError` shape.
10. Emails: verification and reset links enqueued on a BullMQ `email` queue (the worker implementation is 1A.7; until then a dev-only consumer in the API sends through Mailpit SMTP, guarded by `NODE_ENV !== 'production'`, and removed in 1A.7). No token values in logs.
11. OAuth providers (Google, Apple, Facebook, Microsoft) enabled only when their client id/secret env vars exist (0.6 pending); `GET /v1/auth/oauth/{provider}/start` returns 404 `PROVIDER_NOT_CONFIGURED` otherwise. State + PKCE per SECURITY.md.
12. Fastify-level errors (malformed JSON, oversized body, unsupported media type) keep their 4xx status and `ApiError` shape through the global filter; tests.
13. Integration tests against the local stack: sign-up -> verify email (token taken from the queued job) -> sign-in (cookie and bearer) -> session -> sign-out; wrong password; unverified sign-in policy; reset flow; add role + AuditLog row; TOTP enroll/verify/disable; rate limit hit; token hash stored; seed users can sign in with `SEED_USER_PASSWORD`.
