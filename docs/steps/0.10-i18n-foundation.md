# Step 0.10 – i18n foundation

Plan reference: `docs/PLAN.md` step 0.10. Owner: i18n-maintainer. Branch: `feat/0.10-i18n-foundation`.

## Goal

`packages/i18n` holds ICU MessageFormat catalogs for en, fr, de, pt, es with `en` as the source of truth, `packages/shared` defines the supported locales and fallback rules, and `pnpm i18n:check` guards catalog consistency in CI.

## Tasks

1. `packages/shared/src/locale.ts`: `SUPPORTED_LOCALES = ['en', 'fr', 'de', 'pt', 'es'] as const`, `Locale` type, `DEFAULT_LOCALE = 'en'`, `isLocale()`, and `resolveLocale(input)` which accepts BCP 47 tags (`fr-LU`, `pt-PT`, `de-CH`) and Accept-Language style lists, matches on the primary subtag and falls back to `en`. Unit tests cover exact, regional, list with q-values, unknown, empty input.
2. `packages/i18n/messages/<locale>.json`: nested JSON namespaced by feature. `en` starts with a minimal real set (`common.*`: app name, loading, error, retry, cancel, save; `locale.*`: the five language names in their own language). The other four are `{}`.
3. `packages/i18n/src/index.ts`: exports the catalogs typed from `en.json`, `getMessages(locale)` which deep-merges the locale catalog over `en` (fallback), and a `MessageKey` type of dot paths.
4. `packages/i18n/scripts/check.ts` run by `pnpm --filter @photoo/i18n i18n:check` and root `pnpm i18n:check`:
   - fails on keys present in a locale but not in `en` (extra keys)
   - fails when a translated message's ICU placeholders or plural/select argument names differ from `en`, or a message does not parse as ICU (use `@formatjs/icu-messageformat-parser`, exact version)
   - reports missing keys per locale; fails on them only with `--strict`. Non-strict until step 2.3, because non-en catalogs are empty by design and fall back to `en`. `docs/ARCHITECTURE.md` "missing keys fail CI" becomes true when CI switches to `--strict` in 2.3.
5. `packages/i18n/needs-review.json`: `{}` placeholder the agent rules refer to.
6. CI: add `pnpm i18n:check` to `.github/workflows/ci.yml` after lint.
7. Tests for the checker's pure functions (extra key, placeholder mismatch, plural mismatch, invalid ICU, missing key strict vs non-strict) and for `getMessages` fallback.
8. Update `CLAUDE.md` Commands (remove `i18n:check` from "planned") and note the strict switch in `docs/PLAN.md` step 2.3.
