## Decisions for this step

- **Coordinates without a geocoder** (open decision O6).
  - `CreateRequestRequestSchema` needs `location`, and no geocoding vendor is chosen.
  - `GET /v1/cities` items gain `location`: the average of the published profiles' locations in that city, snapped to 0.01° (the same privacy rule as search).
  - The form offers two sources:
    - pick the city from the autocomplete, which sets `location` to the centroid and fills `address.city` and `countryCode`;
    - "use my location" (browser geolocation on click, rounded to 2 decimals, city still typed).
  - The street address fields stay free text and are only visible to the owner (1A.5 rule). The submit is disabled until a location source is set, with an explanation.
  - When O6 is decided, a geocoder replaces the centroid without a contract change.
- **Routes** (all behind the sign-in redirect with the sanitised `next`):
  - `/{locale}/requests/new`: replaces the 1B.3 placeholder. With `?photographer={slug}`, it shows that photographer's card and products above the form. It explains that requests go to every matching photographer, and each product tier offers "request this package" (direct quote).
  - `/{locale}/requests`: my requests (`GET /v1/requests/mine`, cursor "load more"), with a status badge and quote count.
  - `/{locale}/requests/{id}`: request detail plus quotes (`GET /v1/requests/{id}/quotes`), a side-by-side compare of sent quotes (total, line items, valid until, photographer card), and accept, decline and cancel.
  - `/{locale}/quotes`: quotes I received as a client (`GET /v1/quotes/mine?role=client`), including direct quotes, and `/{locale}/quotes/{id}` for the detail.
  - All pages are `noindex` (private) and `dynamic`, never cached.
- **Mutations.**
  - Client components call the API directly through `@photoo/api-client` (browser `fetch`, credentials included), the same pattern as 1B.2's account panels, not server actions. The browser already holds the session cookie, and the API's OriginGuard is the CSRF defence, so there's nothing extra to forward.
  - Every action calls `router.refresh()` on success so the server-rendered page re-fetches, and maps API errors to i18n messages: 409 "this quote is no longer available", 422 field errors onto the form (or the request/quote's own `errors.invalid` notice for a non-field one), 429 "slow down".
  - Accept and decline ask for confirmation in a dialog. After accept, the page says "Booking and payment arrive soon"; 1B.7 replaces this.
- **Money.**
  - The budget inputs are whole currency units converted to cents. Currency comes from the chosen country (`Country` via the API, never hardcoded).
  - Quote amounts are displayed exactly as the API returns them via `lib/money.ts`. The client never computes totals or fees.
  - `platformFee` isn't shown to the client, because it comes out of the photographer's side (`docs/PAYMENTS.md`).
- **Form.**
  - Title, category, description, event date (native `datetime-local`), flexible date, location as above, address, budget min/max, and usage with licence labels from `common.licenceUsages`.
  - Client-side validation mirrors `CreateRequestRequestSchema` through `@photoo/shared`. The server remains the authority.
- **Nav.** The signed-in user menu gets "My requests" and "Quotes".
- **Out of scope.** Chat links (1B.6), checkout (1B.7), the photographer quote inbox and sending quotes (1B.8).

## 1B.5a tasks (api-developer)

1. Contract: `location: LatLngSchema` on `CitySummarySchema`; regenerate openapi and api-client.
2. Cities repository: `AVG` of `ST_Y`/`ST_X` of the profile location per group, snapped to 2 decimals in SQL. Integration test: the centroid is snapped, and unpublished profiles don't influence it.

## 1B.5b tasks (web-developer)

1. Routes, server actions and components above: `request-form.tsx`, `location-picker.tsx` (reusing the 1B.4 city autocomplete), `quote-card.tsx`, `quote-compare.tsx` and `status-badge.tsx`.
2. The profile CTA and product list link to `requests/new?photographer=`. The direct quote button posts `productTierId` and redirects to `/{locale}/quotes/{id}`.
3. i18n keys under `web.requests.*` and `web.quotes.*` in `en`, removing the now-unused `web.requests.placeholder.*`. i18n-maintainer drafts the other locales.
4. Tests:
   - form validation and cents conversion;
   - location source required;
   - error mapping for 409, 422 and 429;
   - accept and decline disabled for non-`sent` quotes;
   - compare only lists `sent` quotes;
   - signed-out redirect keeps `next`;
   - the direct quote action never sends a price.
   - Web coverage must not drop.
5. Manual check on the local stack with the seeded client: create a request, see the seeded quote, accept it, and see the request become `booked`.
