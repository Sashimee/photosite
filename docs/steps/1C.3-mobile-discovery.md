# Step 1C.3 – Mobile discovery and photographer profile

Plan reference: `docs/PLAN.md` step 1C.3. Owner: mobile-developer. Blocked by 1C.1 (merged) and 1A.4 (merged); `docs/PLAN.md` does not require 1C.2, and this step deliberately keeps browsing signed-out so the app is useful before an account exists — the same rule the web follows.

| Sub-step | Scope | Branch |
|----------|-------|--------|
| 1C.3a | Discover tab: search, filters, city autocomplete, near-me, results | `feat/1C.3a-mobile-discovery` |
| 1C.3b | Photographer profile screen: portfolio, products and tiers, request-a-quote entry | `feat/1C.3b-mobile-profile` |

## What the API already gives us

- `GET /v1/photographers` with the filters 1B.4 settled: `city`, `countryCode`, category, language, price bounds, `lat`/`lng` + `radiusKm`, cursor pagination.
- `GET /v1/photographers/{slug}` for the full profile.
- `GET /v1/cities?countryCode=&q=&limit=` returning `{ slug, name, countryCode, photographerCount }`, already public and cached, built in 1B.4a to feed exactly this kind of autocomplete.

Nothing new is needed from the API for this step. That is worth stating, because it means 1C.3 is pure client work and can run entirely in parallel with lane A.

## Decisions for this step

- **Parity of behaviour with the web, not parity of layout.** The same filters, the same cursor pagination and the same money formatting through the shared helper; native list and sheet patterns rather than a transposed web page.
- **Search state lives in the URL**, via `expo-router` search params, so a result list survives a tab switch, a deep link and the Android back button. This is the same reason the web put it in the query string, and it is what makes "back" behave.
- **Location is requested on tap, never at launch.** `expo-location` is called only when the user taps "near me", with the foreground permission and a purpose string. Coordinates are rounded to 2 decimals (~1 km) before they go in a request, exactly as the web does, and are never stored — so no consent record is needed, matching `COMPLIANCE.md`.
  - A denied permission is a normal state, not an error: the button explains what it would do and offers Settings. An app that dead-ends on a denied permission is an app that loses the user.
  - `app.config.ts` gains `NSLocationWhenInUseUsageDescription` and the Android foreground location permission. Background location is never requested — it would change the store review surface and the privacy manifest for no feature.
- **No map.** 1B.4 deferred it because a tile provider is a vendor and privacy decision (open in `docs/DECISIONS.md`), and shipping a map on mobile before that decision would force it silently. Results are a list.
- **City autocomplete** is a debounced (250 ms) call to `/v1/cities`, cancelled on each keystroke, with the last successful result kept visible while the next loads so the list does not flicker empty.
- **Images.** `expo-image` with the public variant URLs, explicit `contentFit` and a blurhash-free placeholder colour from the token scale. Portfolio images are served from the public bucket and are EXIF-stripped by the worker (1A.3), so nothing here has to strip anything — but the plan records that fact so nobody assumes otherwise.
- **The list is virtualised** (`FlashList` or `FlatList` — pick whichever 1C.1's Expo SDK ships without a new native dependency, and say which in the PR) with `onEndReached` paging on the existing cursor, a footer spinner, and an empty state that offers to clear filters.
- **Offline and failure are designed, not incidental.** A failed search shows a retry, a failed profile load shows a retry, and neither shows a raw error payload. There is no offline cache in this step; that is a deliberate omission recorded here rather than an oversight.
- **The profile screen is readable signed-out.** Portfolio, products, tiers and the "from" price all render. Only the "request a quote" action requires a session: tapping it while signed out routes to sign-in and returns to the profile afterwards, which is why the return-path handling from 1C.2a is a dependency in practice even though the plan does not list it as one.
- **Products and tiers show money through the shared helper**, integer cents and ISO currency, never a hand-rolled format — the same rule as everywhere else in the repo.
- **Deep links.** `photoo://photographers/{slug}` resolves to the profile screen, so a share link and a later push notification land in the right place. Universal links stay out until the store accounts exist (1C.2's follow-up), and the scheme link works today without them.
- **Sharing** uses the system share sheet with the web URL (`WEB_APP_URL/{locale}/photographers/{slug}`), not the app scheme, so a shared link opens for someone who does not have the app.
- **Accessibility is not deferred.** Every touch target is at least 44×44, images carry labels, and the filter sheet is reachable with a screen reader. Retrofitting this after the screens exist costs more than writing it now.

## 1C.3a tasks

1. Replace the Discover tab placeholder with the search screen: header search field, filter sheet (city, category, language, price range), "near me", result list, empty and error states.
2. `src/lib/search-params.ts` mapping typed filters to and from `expo-router` params, validated with a schema derived from the shared `PhotographerSearchQuerySchema` — never a second hand-written copy of the rules.
3. City autocomplete component against `/v1/cities`.
4. `src/lib/location.ts` wrapping `expo-location`: permission state, one-shot position, rounding, and the denied path.
5. i18n keys under `mobile.discovery.*` in `en`.
6. Tests: params round-trip through the URL, a denied permission renders the explain state and issues no request, the autocomplete debounces and cancels, paging appends without duplicating, an empty result renders the clear-filters state, and money formatting comes from the shared helper.

## 1C.3b tasks

1. Profile screen: header (avatar, name, headline, city, categories, languages), portfolio grid with a full-screen viewer, products with tiers and prices, and the request-a-quote button.
2. Signed-out behaviour: everything renders, the quote action routes to sign-in and returns.
3. Deep link route and the share action.
4. Tests: renders signed-out, the quote action's redirect and return, a 404 slug renders not-found rather than crashing, and the portfolio viewer's paging.

## Human follow-ups

None new. This step needs no account, no key and no vendor: it runs entirely against endpoints that already exist. The map decision (`docs/DECISIONS.md`) stays open and is not forced by this step.
