The audit-trail viewer listed in `docs/PLAN.md` for 1D.1 needs the audit-log query endpoint from **1A.11**, which is not built. It moves to a later sub-step rather than shipping a fake; this deviation is deliberate and recorded here so the plan table and reality stay honest.

## What the API already gives us

- `requireAdminSession` (`apps/api/src/common/auth/require-admin.ts`) demands the `admin` role **and** a session whose `twoFactorVerifiedAt` is set and under 12 hours old, otherwise `403 { code: 'TWO_FACTOR_REQUIRED' }`. Admin 2FA is therefore already mandatory server-side; the UI's job is to make that state understandable, not to enforce it.
- Sign-in returns `{ twoFactorRequired: true }` for a TOTP-enabled account, and `POST /v1/auth/sign-in/totp` completes it. `POST /v1/auth/totp/enroll|verify` exist for an admin who has no second factor yet.
- The session cookie is `photoo_session`, `SameSite=Lax`, host-only, and `OriginGuard` (D21) rejects a mutation whose `Origin` is not in `WEB_ORIGINS` or whose `Sec-Fetch-Site` is `cross-site`.

## Decisions for this step

- **Same-site, not cross-site.** `admin.photoo.lu` and the API host are both under `photoo.lu`, so `SameSite=Lax` still sends the session cookie and `Sec-Fetch-Site` is `same-site`. The only requirements are that the admin origin is added to `WEB_ORIGINS` and to the CORS allow-list. No cookie-domain widening, no bearer token in the browser, no second auth mechanism.
- **The preview needs no DNS from Alex.** There is no `admin.footoo.bas.lu` and creating one needs a DNS record and a certificate. Instead the preview serves the admin app under Next.js `basePath: '/admin'` on the existing preview host, which is same-origin with the API and therefore needs nothing new. Production keeps `admin.photoo.lu`; `basePath` comes from an env var so one build serves both shapes. Recorded as a follow-up, not a blocker: when Alex wants the real subdomain, add the DNS record and drop the env var.
- **English only, strings still in `packages/i18n` under `admin.*`.** Staff tooling does not need locale routing, so there is no `[locale]` segment, but keeping the strings in the catalog means `pnpm i18n:check` still covers them and translating later is not a rewrite.
- **`noindex` unconditionally**, plus `X-Robots-Tag: noindex, nofollow` from `next.config.ts`. The admin app never reads `ALLOW_INDEXING`; there is no environment in which it should be indexed.
- **Login is a single screen with three states**: password, TOTP code, and "enrol a second factor". An admin who signs in correctly but has no TOTP is sent to enrolment and cannot reach anything else until `verify` succeeds — the API would refuse them anyway, so the UI makes the reason explicit instead of showing a bare 403.
- **`TWO_FACTOR_REQUIRED` is a first-class state, not an error toast.** Because the API expires the 2FA stamp after 12 hours, an admin mid-session will hit it. The fetch wrapper recognises the code, routes to a re-verification prompt that preserves the intended destination, and returns the user there afterwards. A 401 clears the session and returns to login.
- **Server-side session check in the layout.** The guarded layout calls `GET /v1/auth/session` server-side (the `serverApi()` pattern from 1B.5b, copied rather than shared for now — `apps/web` and `apps/admin` are separate apps and one shared helper across them is a refactor this step does not need to invent). Non-admins get the same "not found" as an unknown route: an admin surface should not confirm its own existence to a signed-in client.
- **CSP is stricter than the public site's.** No analytics, no third-party scripts, no `unsafe-inline` beyond what Next.js requires, `connect-src` limited to the API origin. The admin app loads no Google tags and sets no analytics cookies, so it has no consent banner and nothing to consent to.
- **Data tables are one primitive, not a library per page.** A `DataTable` component taking columns, rows, a keyset cursor and a loading state, built on the same shadcn/ui primitives as `apps/web` (Tailwind config and tokens copied from the web app, not imported, for the same reason as `serverApi`). Server-side pagination only — every admin list is backed by a keyset endpoint, and client-side sorting of one page would lie about the data.
- **Every destructive action is a confirm dialog naming the subject** ("Suspend photographer Sofia Martins?"), and the confirm posts through the fetch wrapper so `TWO_FACTOR_REQUIRED` still applies. 1D.5's finance actions re-prompt for 2FA on top of this; the wrapper is written now so that step only sets a flag.
- **No impersonation, ever.** `docs/PLAN.md` calls for an "impersonation-free support view" and this shell has no code path that assumes another user's identity. Worth stating because it is the obvious thing a later step might reach for.
- **Deployment is not in this step.** The preview compose gains an admin service in a devops-engineer step once there is something to deploy; 1D.1 is verified locally and in CI.

## 1D.1a tasks

1. Replace the placeholder package with a Next.js 16 App Router app matching `apps/web`'s versions exactly (React, Next, Tailwind, shadcn/ui, next-intl for the catalog only), scripts `dev`, `build`, `lint`, `typecheck`, `test`, and `apps/admin/.env.example` updated.
2. `src/lib/api.ts` (browser fetch wrapper with the `TWO_FACTOR_REQUIRED` and 401 handling) and `src/lib/server-api.ts` (cookie-forwarding server fetch).
3. `app/(auth)/sign-in/page.tsx` with the three states, `app/(admin)/layout.tsx` with the server-side guard, and a placeholder `app/(admin)/page.tsx` that only says who is signed in and when their second factor expires.
4. `next.config.ts`: `basePath` from env, the `noindex` header, and the CSP.
5. API-side: add the admin origin to `WEB_ORIGINS` handling and the CORS allow-list where they are configured — one env value, no code branch per environment.
6. Tests (vitest + Testing Library, as `apps/web` uses):
   - the guarded layout redirects a signed-out visitor to sign-in and 404s a signed-in non-admin;
   - `twoFactorRequired` routes to the code state and a wrong code shows the mapped error;
   - an admin without TOTP is routed to enrolment and cannot reach the shell;
   - a mid-session `TWO_FACTOR_REQUIRED` re-verifies and returns to the intended page;
   - a 401 clears the session;
   - the `noindex` header is present.

## 1D.1b tasks

1. `DataTable` with keyset pagination, empty, loading and error states, and a column definition type shared by later lane D steps.
2. App shell: sidebar navigation (sections stubbed with a clear "available after 1A.11" state rather than dead links), header with the signed-in admin and a sign-out action, and an error boundary that never prints a raw API payload.
3. A health page showing the API's readiness endpoint and the app's build info — the first genuinely useful admin page, and a real exercise of `DataTable` and the fetch wrapper.
4. Tests: pagination advances by cursor and never refetches page one on back, the error boundary renders a mapped message, and a render against the real `en` catalog.
