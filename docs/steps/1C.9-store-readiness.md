## Decisions for this step

- **Account deletion uses the existing API, not a new one.** `POST /v1/me/data-requests` with `type: 'delete'` (the same call the web's `apps/web/src/app/[locale]/account/delete-account-action.tsx` uses) soft-deletes at once and revokes every session; the 30-day grace and cancel link work as on the web. The app shows what happens and when, asks for explicit confirmation, then signs out locally. Apple guideline 5.1.1(v) and Google Play's account-deletion policy both require deletion to be *initiated* in the app, not only a link to a website.
- **Data export is offered next to deletion** (`type: 'export'`) because it is the same screen and the same API, and Art. 20 portability is cheaper to show than to explain; the download opens the presigned URL in the browser after an https check, as receipts do (1C.6d).
- **A web URL for deletion is still needed** for the Play listing ("delete your account without reinstalling"). The web already has one (`/account`), so 1C.9c lists it rather than building anything.
- **Declarations are generated from what the app actually ships**, not from a template: 1C.9b inventories `apps/mobile/package.json` native modules (Stripe, Sentry, expo-secure-store, expo-crypto, expo-image-picker, expo-location, expo-notifications, …) and each one's own privacy manifest, then writes `docs/store/privacy-declarations.md` with the App Store label answers and the Play data-safety answers, each line pointing at the code that justifies it. Analytics stays "not collected" until 1C.8c ships Firebase; that is stated, not assumed.
- **No ATT prompt** (1C.8 decision), so `NSUserTrackingUsageDescription` stays absent and the manifest declares no tracking domains.
- **Listing texts live in the repo** (`apps/mobile/store/<locale>/…` in the shape EAS Metadata reads, `store.config.json`), English as source, other locales as drafts. Nothing is pushed to the stores until the accounts exist.
- **No placeholder art is submitted.** 1C.9e waits for the brand kit; the current solid-colour placeholders (O5) are fine for TestFlight/internal testing only.

## Tasks

1. **1C.9a** — Account tab → "Delete account" and "Download my data": explain consequences (bookings in progress, payouts held, 30-day grace, cancellable from the email link), require confirmation, call the data-request API, handle every error the API returns (an existing pending request comes back as `200` with that row; in-progress bookings if the API blocks them), sign out locally after deletion. Export: create, show status, open the download. i18n `mobile.account.deletion.*`, `mobile.account.export.*`. Tests per the API's real shapes. Reviews: code-reviewer, security-reviewer, compliance-reviewer.
2. **1C.9b** — privacy manifest entries for each required-reason API the app and its SDKs use; `docs/store/privacy-declarations.md`; fold in the rows already in `human-followups.md` (verification documents #595, Stripe SDK 1C.6b, portfolio originals #589).
3. **1C.9c** — listing texts in EAS Metadata shape; support URL, privacy policy URL, account-deletion URL.
4. **1C.9d** — once the Expo project exists: `eas.json` submit profiles, a manual GitHub Actions workflow for build + submit, secrets as GitHub/EAS secrets only.
5. **1C.9e** — once the brand kit lands: icons (iOS, Android adaptive), splash, screenshots per required device size.
