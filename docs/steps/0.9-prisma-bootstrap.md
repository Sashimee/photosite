# Step 0.9 – Prisma bootstrap

Plan reference: `docs/PLAN.md` step 0.9. Owner: schema-migrator. Branch: `feat/0.9-prisma-bootstrap`.

## Goal

`packages/db` owns a working Prisma setup against the local stack (0.3): datasource, PostGIS enabled by migration, and the first reference data (`Country` with Luxembourg, `PlatformSetting` with fee and auto-release defaults) seeded idempotently.

## Tasks

1. Dependencies in `packages/db`, exact versions: `prisma` (dev) and `@prisma/client` on the latest stable 7.x (not the 8 release candidate), plus the driver adapter `@prisma/adapter-pg` and `pg` required by Prisma 7.
2. `prisma.config.ts` reading `DATABASE_URL` from the environment; fail with a clear message when it is missing.
3. `prisma/schema.prisma`: `postgresql` datasource with the `postgis` extension, `prisma-client` generator with output under `src/generated/` (gitignored, excluded from lint/format).
4. Models per `docs/DATA-MODEL.md`:
   - `Country`: `code Char(2)` PK, `name`, `enabled`, `currency Char(3)`, `vatRate` (decimal percentage), `requiredDocuments Json`, `legalTexts Json`, `defaultLocale`, timestamps.
   - `PlatformSetting`: `key` PK, `value Json`, `updatedByAdminId String?` (plain column; FK to `User` added in 1A.1), timestamps.
5. Migrations: `init_postgis` (hand-written `CREATE EXTENSION IF NOT EXISTS postgis`) then `country_platform_setting`.
6. Scripts in `packages/db`: `generate`, `migrate:dev`, `migrate:deploy`, `seed`; generate runs before `build`/`typecheck` so CI works without a database.
7. `src/seed.ts`: upsert Luxembourg (`LU`, EUR, VAT 17, enabled, defaultLocale `fr`, required documents `autorisation_etablissement`, `vat_number`, `id_document`, `proof_of_address` with English labels and accepted MIME types) and settings `feePercent = 5`, `autoReleaseDays = 7`. Idempotent: running twice changes nothing.
8. `src/index.ts` exports a `createPrismaClient(databaseUrl)` factory and the generated types.
9. Test: a Vitest integration test that runs against `TEST_DATABASE_URL` and asserts the seed is idempotent and the LU row matches; skipped with a visible reason only when `TEST_DATABASE_URL` is unset (CI has no database until 1E.4).
10. Verify locally: `pnpm stack:up`, `migrate:dev`, `db:seed` twice, `SELECT postgis_version()`; then root `pnpm format:check lint typecheck test build`.

## Out of scope

Identity models (1A.1), zod enums in `packages/shared`, CI database service (1E.4).

## Done when

- Migrations apply on a fresh `stack:reset` database, seed is idempotent
- All root checks green, CI green
- PR into `dev` merged (Alex's instruction on 2026-09-16: merge after each step)
