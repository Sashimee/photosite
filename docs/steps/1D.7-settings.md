## What the API gives us today

`apps/api/src/modules/admin/admin-settings.controller.ts`, on the **`superadmin`** permission (not a lesser one — changing the fee changes what every future booking charges):

- `GET /v1/admin/settings` → `{ feePercent, autoReleaseDays }`.
- `PATCH /v1/admin/settings` → the same two fields, partial, audited as `platform_settings.updated` with before/after.

That is the whole surface. Of the six subjects `docs/PLAN.md` names, **four have no API at all**: feature flags, countries enable/disable, legal text versions, email template preview. `PlatformSetting` is a key/value table so flags and versions have somewhere to live, and `Country` already has `enabled`, `legalTexts` and `vatRate` columns — but nothing writes any of them.

## The fee has two readers that disagree (#193)

This is the finding that reshaped the step, and 1D.7b must not ship on top of it:

- `apps/api/src/common/platform-settings/platform-settings.service.ts` reads `feePercent` through a **30-second in-process cache**, and falls back to `DEFAULT_PLATFORM_SETTINGS.feePercent = 5` when the row is missing or not a number.
- `apps/api/src/modules/quotes/quotes.service.ts:626` reads the same row **directly from the database on every quote**, and throws `quotes: PlatformSetting "feePercent" is missing or invalid` when it is absent.

Two consequences, both real:

1. **A missing row shows the admin a fee that quoting refuses to use.** The settings screen would display 5 % as though it were configured, while every attempt to create a quote fails. The screen must distinguish "configured" from "defaulted", which means the API must tell it which one it is.
2. **`invalidate()` only clears the instance that served the `PATCH`.** It is an in-memory field. The moment the API runs more than one replica — or the worker computes a payout, being a separate process entirely — a fee change is live on one instance and up to 30 seconds stale on the others. Money computed at two rates concurrently is not a rounding difference, it is two different answers to "what did we charge".

The preview runs a single API container, so this is latent rather than currently broken. It stops being latent the first time anything scales. 1D.7a resolves it by making one reader authoritative rather than by adding a third.

`Booking.feePercent` is a snapshot taken at creation (`schema.prisma:721`), so a fee change never rewrites an existing booking. That part is already right, and the settings UI should say so — an admin editing a fee needs to know whether it is retroactive, and the honest answer is no.

## Decisions for this step

- **The fee has one reader.** 1D.7a deletes the divergence: `quotes.service.ts` goes through `PlatformSettingsService`, and the service adopts quoting's loud failure instead of its own silent default. A missing `feePercent` is a misconfiguration, not a 5 %.
- **Cross-process invalidation, not a shorter TTL.** Shortening the TTL narrows the window and keeps the bug. The write publishes on Redis (already a dependency) and every instance drops its cache. If that proves larger than this step, the fallback is to drop the cache entirely and read the row per use — a single indexed primary-key lookup, which is what quoting already does today without complaint. Either is correct; a tuned TTL is not.
  - **1D.7a took the fallback: the cache is gone.** `PlatformSettingsService` reads `feePercent`/`autoReleaseDays` straight from `PlatformSetting` on every call, the same primary-key lookup quoting already made with no complaint. A Redis publish/subscribe invalidation channel would still leave a window between the write committing and every subscriber processing the message, plus a new failure mode (a subscriber that missed the message, or reconnects mid-flight, serving stale data indefinitely instead of for at most 30s) — solving that properly means the write side has to wait for every instance to ack, which is more machinery than a single-digit-millisecond read. Reading the row on every call has no window at all: the value returned is whatever's in the row at the moment the transaction that changed it committed, everywhere, always. `quotes.service.ts` now calls `PlatformSettingsService.getFeePercent()` instead of keeping its own copy of the same query, so there is exactly one reader for the fee.
- **Changing the fee is confirmed, and the confirmation states the blast radius**: the new percentage, that existing bookings keep their snapshot, and that every quote created from now on uses it. Typed confirmation, not a bare OK.
- **Every setting screen shows who changed it last and when.** `PlatformSetting.updatedByAdminId` is recorded but never surfaced, and every write is already audited. A settings page with no history is where an unexplained fee change becomes unattributable.
- **Feature flags are booleans with a description, and the list is defined in code.** A free-text key/value editor on a table the API reads by key is a way to create a flag nothing reads, or to typo a live one into being off. The API publishes the known flags; the screen toggles those.
- **Disabling a country is not deleting it.** `Country.enabled` gates new sign-ups, new profiles and new requests in that country; it never hides existing users or breaks their bookings. The confirmation says which of the two it is, with the count of accounts affected.
- **Legal text versions are append-only and stored per country** (`Country.legalTexts` is already a `Json` column). Publishing a new version does not overwrite the old one, because `ConsentRecord.policyVersion` points at what a user actually agreed to — 1B.10's consent records are meaningless if the version they name can be edited afterwards. This is the same append-only reasoning as consent itself.
- **`policyVersion` is read by 1B.10 and written here.** The two steps must agree on the shape before either ships; 1B.10a is planned and unstarted, so 1D.7a defines it and `docs/steps/1B.10-consent.md` gets a pointer.
- **The email template preview renders, and never sends.** 1D.7c renders react-email templates server-side with sample data and shows the HTML in a sandboxed frame. No "send test to me" button in this step — a preview endpoint that can be made to send mail is an open relay with extra steps. If a real send is wanted later it is its own step, rate-limited and restricted to the signed-in admin's own address.
- **`superadmin` stays the permission for all of it.** Nothing here is a routine support action.

## 1D.7a tasks (api-developer)

1. Make `PlatformSettingsService` the single fee reader: `quotes.service.ts` uses it, the silent default is removed in favour of the explicit failure, and the `GET` response distinguishes a configured value from an absent one.
2. Cross-instance cache invalidation over Redis (or remove the cache — see the decision above; whichever is chosen, record which and why in this file).
3. Feature flags: a code-defined list, `GET`/`PATCH` on the existing settings routes, audited.
4. `PATCH /v1/admin/countries/{code}` for `enabled`, `vatRate` and `defaultLocale`, audited, with the affected-account count available to the UI.
5. Legal text versions: append-only writes to `Country.legalTexts`, a published `policyVersion`, and a read endpoint 1B.10 can consume.
6. Regenerate `openapi.json` and the api-client.
7. Tests: a missing `feePercent` fails quoting **and** is reported as unconfigured by the settings endpoint rather than as 5; a `PATCH` is visible to a second instance (or the cache is gone and the test asserts that); disabling a country blocks a new request in it and leaves an existing one working; a legal text version is never overwritten; every mutation writes an `AuditLog` row.

## 1D.7b tasks (web-developer)

Screens for everything above: fee and auto-release with the typed confirmation and the blast-radius text, flags, the country table, legal text versions with their history, each showing last-changed-by and last-changed-at. i18n under `admin.settings.*`, English only. Tests: the confirmation is required and names the new value; an unconfigured fee renders as unconfigured, not as 5; a country toggle names the country and the affected count; one test renders against the real `en` catalog.

## 1D.7c tasks

Email template preview: a server-rendered preview per template and locale with sample data, in a sandboxed frame, no send path. Its own PR.

## Human follow-ups

- **The launch fee.** `DEFAULT_PLATFORM_SETTINGS` and the seed both say 5 %, matching `CLAUDE.md`. Confirm 5 % is the number the platform launches with before anything charges a real card, because `Booking.feePercent` snapshots it and changing it later does not revisit bookings already taken.
- **Which countries are enabled at launch.** Luxembourg first is decided; whether the neighbours are open on day one is not, and the country table is the switch.
- **Legal text ownership.** Publishing a legal text version through this screen is publishing a legal document. Confirm the lawyer's text is the source and this screen only versions it — with the 0.7 lawyer conversation.
