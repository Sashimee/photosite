## What this step actually does

- **Tune Helmet for an API rather than a page.** Defaults are written for HTML. Decide each header deliberately: `Content-Security-Policy` is close to meaningless for JSON responses but matters for the OpenAPI page if one is served; `X-Frame-Options`/`frame-ancestors` matter only for HTML responses; HSTS must be on in production and must not be set on plain HTTP in local dev. Every header that stays gets a one-line reason, and a test asserts the response header set so a future dependency bump cannot silently change it.
- **Audit rate-limit coverage route by route.** `RedisRateLimiter` exists and several modules use it, but nothing proves *every* mutating route is covered. Produce a table of every registered route against its limit, and fix the gaps. Missing limits are found by enumerating the router at runtime, not by reading files — a route that nobody remembers is exactly the one that is unprotected.
- **Uniform error shape.** Every error must be `{ code, message }` with the documented status. Audit for handlers that leak a Prisma error, a zod issue tree or a stack; assert the shape in a test that walks the route table and sends a deliberately invalid request to each.
- **404 vs 403 discipline.** A resource the caller may not see must 404, not 403, wherever a 403 would confirm existence (already the rule for chat and profiles). Audit consistency across modules and document the intended rule where 403 *is* correct (a role the caller lacks on a resource they legitimately know exists).
- **Response header hygiene.** No `x-powered-by`, no framework version, no internal hostnames in errors.
- **Timeouts.** A request with no timeout is a slow-loris budget. Set a server-level timeout, and confirm outbound calls (S3, ClamAV, SMTP, Redis) each have one — an unbounded outbound call turns one slow dependency into an exhausted connection pool.
- **Socket.IO gets the same audit as HTTP**: handshake auth, membership checks, per-event rate limits, payload size caps, and what happens to a connection whose session is revoked mid-stream (the shape of #101, which stays open until this pass or its own fix closes it).
- **Dependency audit** in CI: `pnpm audit` at a defined severity threshold, wired so a new advisory fails the build rather than being discovered later. The repo's `minimumReleaseAge` policy stays exactly as it is — never add an exclusion to it.
- **The OpenAPI document is checked for accidental exposure**: no route documented that is not meant to be public, no example containing a real-looking secret, and `DISABLED_BETTER_AUTH_PATHS` still actually disabled (a test asserts each returns 404, because that list is easy to regress when the library is upgraded).

## Tasks

1. Route inventory produced at runtime (method, path, guard, rate limit, auth requirement) written to a test fixture, with a test that fails when a new route appears without a limit or without an auth decision recorded. This is the durable part: it turns "we audited it once" into "it cannot regress silently".
2. Helmet configuration plus the header assertion test.
3. Error-shape and 404/403 audit with fixes.
4. Timeouts, server and outbound.
5. Socket.IO audit and fixes.
6. `pnpm audit` in CI.
7. A security-reviewer pass over the result, findings filed as issues rather than fixed inline where they are not trivial.

## Second pass (after 1A.8 and 1A.11)

Re-run items 1, 3 and 7 over the payments and admin routes specifically, and add: webhook signature verification is scoped to exactly one route with a raw body; no admin route returns more personal data than its screen needs; refunds and role changes require fresh 2FA as `docs/steps/1A.11-admin-api.md` specifies.
