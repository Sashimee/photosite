# Step 1C.4 – Mobile requests and quotes

Plan reference: `docs/PLAN.md` step 1C.4 — "create request, my requests, quotes, accept/decline". Owner: mobile-developer. Blocked by 1C.2 (merged) and 1A.5 (merged); both are in place, and `apps/mobile/app/(tabs)/requests.tsx` is still a `TabPlaceholderScreen`.

The web equivalent is `docs/steps/1B.5-request-flow.md`, already merged and shipped. **This step is a port of decisions already taken, not a fresh design.** Where the web made a call, mobile keeps it; the sub-steps below exist only where a native platform forces a different answer.

| Sub-step | Scope | Branch |
|----------|-------|--------|
| 1C.4a | Create request (form, location, date) | `feat/1C.4a-mobile-request-form` |
| 1C.4b | My requests, request detail with quotes, accept/decline/cancel | `feat/1C.4b-mobile-requests-list` |

## Inherited from 1B.5, restated so it is not re-litigated

- **Money is displayed exactly as the API returns it** through `apps/mobile/src/lib/money.ts`. The client never computes a total or a fee. Budget inputs are whole currency units converted to cents; currency comes from the `Country` record, never hardcoded.
- **`platformFee` is never shown to the client** — it comes out of the photographer's side (`docs/PAYMENTS.md`).
- **Accepting a quote only records `accepted`.** Checkout is 1C.6 and needs 1A.8. The success state says payment arrives soon; it does not imply money moved.
- **Error mapping**: 409 "this quote is no longer available", 422 field errors onto the form, 429 "slow down". Same three, same meanings.
- **Accept and decline are confirmed** before they fire.
- **Street address is free text, owner-visible only**; location is snapped to 0.01° (the 1B.4 privacy rule).

## Where native forces a different answer

- **The date picker is a new dependency, and that is the one real decision here.** Web used `datetime-local`; React Native has no equivalent. The standard answer is `@react-native-community/datetimepicker` (an Expo-supported package). Two constraints on adding it:
  - It must be installed at a version that satisfies pnpm's `minimumReleaseAge`. **`minimumReleaseAgeExclude` in `pnpm-workspace.yaml` is not to be touched** — if the current version is too new, pin the newest version that is old enough rather than adding an exclusion.
  - It must be added through `expo install` so the version matches the installed Expo SDK, not `pnpm add` with a guessed range.
  If for any reason it cannot be added cleanly, the fallback is three numeric fields with validation — worse, but shippable — and whichever happens gets recorded here.
- **Location comes from the device, not a browser prompt.** `expo-location` is already a dependency and `apps/mobile/src/lib/location.ts` plus `near-me-button.tsx` already handle the permission flow from 1C.3 — reuse them rather than writing a second permission path. The city autocomplete (`city-autocomplete.tsx`) is likewise already there and supplies the centroid, so both of 1B.5's two location sources already exist on mobile.
- **Permission denial is a state, not a dead end.** If location permission is refused, the city autocomplete still sets a location and the form still submits. A form that cannot be completed without granting location is a form that loses the user at the OS dialog.
- **Deep links.** `expo-linking` is configured; a quote notification (1C.5) will link to a quote detail, so the routes get real paths now — `/requests/[id]` and `/quotes/[id]` — rather than being reachable only by tapping through the list.
- **The list is a `FlatList` with cursor paging**, loading the next page on end-reached rather than a "load more" button, with a pull-to-refresh. This is the platform convention and the API is already keyset-paginated.
- **Offline and flaky networks are visible.** A failed fetch on a list shows a retry affordance and keeps whatever was already loaded; a failed *mutation* says it failed and leaves the screen unchanged. Mobile networks fail far more often than the web app's, and a silent failure on "accept quote" is the worst case in this step — the user would believe they had accepted.

## Routes

All behind `RequireSession` (the existing component), which already preserves the intended destination:

- `app/(tabs)/requests.tsx` — replaces the placeholder: my requests from `GET /v1/requests/mine`, status badge, quote count.
- `app/requests/new.tsx` — the form. Reachable from the requests tab and from a photographer profile (1C.3), carrying `?photographer={slug}` the way the web does.
- `app/requests/[id].tsx` — request detail plus its quotes (`GET /v1/requests/{id}/quotes`), accept/decline/cancel.
- `app/quotes/index.tsx` and `app/quotes/[id].tsx` — quotes received as a client, including direct quotes from a product tier.

No side-by-side quote compare on mobile: the web's compare table is a wide-screen affordance. The quote list stays a vertical list of cards carrying the same facts (total, line items, valid until, photographer), which is the information compare existed to deliver.

## Tasks

1. The routes above, reusing `require-session.tsx`, `text-field.tsx`, `primary-button.tsx`, `form-notice.tsx`, `city-autocomplete.tsx` and `money.ts`. No parallel component set.
2. Client-side validation mirrored from `CreateRequestRequestSchema` in `@photoo/shared`; the server stays the authority.
3. i18n under `mobile.requests.*` and `mobile.quotes.*`, English only, replacing the now-unused placeholder key. All text from the catalog.
4. Tests (jest-expo, matching the existing `apps/mobile` suites):
   - cents conversion and form validation;
   - the form submits with a city-supplied location when location permission is **denied**;
   - error mapping for 409, 422 and 429;
   - accept and decline are unavailable for a quote that is not `sent`;
   - accept asks for confirmation before firing;
   - a failed accept leaves the quote unchanged and says so;
   - the direct-quote action never sends a price;
   - one test renders against the real `en` catalog.
   Existing mobile tests already sit close to jest's 30s timeout (`apps/mobile/app/(auth)/sign-in.test.tsx` timed out once on a loaded CI runner). New tests here must not add fake timers or long waits casually; if a test needs more than a second of wall clock, that is a signal the component is doing something it should not.
5. Manual check against the local stack with the seeded client: create a request, see the seeded quote, accept it, and see the request become `booked`.
