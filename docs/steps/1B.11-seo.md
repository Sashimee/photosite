## The constraint that shapes this step

**The preview is `noindex`, and must stay that way.** `NEXT_PUBLIC_ALLOW_INDEXING` is `false` everywhere except production (2.4), which has not been built. So:

- Nothing in this step can be validated by "search for it on Google" — there is no indexable deployment to test against.
- The checks must therefore be **machine-checkable in CI**: the sitemap returns the expected URLs, every indexable page has exactly one canonical, hreflang sets are reciprocal, and the structured data validates against its schema. Those are assertions, not eyeballing.
- The one thing CI cannot prove is how Google actually treats it. That is honest to state now rather than discover at launch, and it is why 1B.11 is a *pass*, not a guarantee.
- **A sitemap must never list a URL that robots disallows.** With indexing off, the sitemap should be absent or empty rather than advertising URLs we tell crawlers to ignore — a contradiction that search engines report as an error and that would ship to production silently if the sitemap ignored the flag.

## Decisions for this step

- **The sitemap is generated from the API, not a static list.** Profiles appear and disappear (unpublished, taken down under #190, suspended), and a stale sitemap of 404s or private pages is worse than none. It reads published profiles and the landing combinations the discovery endpoint actually has, and it must exclude anything whose profile is not published.
- **Only public pages are in the sitemap, and only public pages are indexable.** Everything behind sign-in — requests, quotes, messages, account, and the whole dashboard from 1B.8 — stays `noindex` and absent from the sitemap. This is already the pattern; the step adds a test so a future page cannot quietly join the index.
- **Canonical points at the locale the page is actually on**, with hreflang listing every locale including `x-default`. `localeAlternates()` exists; the gap is coverage — a test that every public route exports metadata using it, rather than each page remembering to.
- **Landing pages must not become doorway pages.** `/photographers/{country}/{city}` with no photographers in it is a thin page that search engines penalise and users bounce from. A landing page with nothing to list should `noindex` itself and say so plainly, rather than rendering an empty grid to be counted as content.
- **Lighthouse CI runs against a built app, not the preview.** It starts the production build locally in CI and measures that, so the budget is reproducible and does not depend on the VPS's load or on CrowdSec. Budgets are set from a first measured run rather than aspirational numbers — a budget nobody can meet gets disabled within a week.
- **The budget fails the build only on the metrics we control.** LCP, CLS and total byte weight are ours. Third-party scripts arrive with 1B.10's consent-gated GTM, which is exactly the thing that will blow a performance budget — so the budget is measured with consent **denied** (the default state for a first visit) and separately reported with it granted, rather than pretending the tag manager is free.
- **Structured data is validated in CI against the schema**, not by pasting into Google's tool by hand. The two JSON-LD builders already have unit tests; this adds validation that the emitted object is well-formed for its type.
