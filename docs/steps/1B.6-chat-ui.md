## Decisions for this step

- **Contract gaps to close first** (1B.6a, same shape as #93 for quotes):
  - `ConversationParticipant` gains a `user` summary (`id`, `displayName`, `avatarUrl`) so the UI can name the other party. No email, no role.
  - `MessageAttachment` gains `fileName`, `mimeType` and `sizeBytes`, taken from the `Upload`, so the thread can render a file chip before the download URL is requested. `kind` stays.
  - Both come from one query, with no N+1.
  - `Conversation` also gains `subjectRef`: `{ type: 'quote', quoteId, requestTitle? }`, so the list can say what the conversation is about without a second call per row.
- **Routes.**
  - `/{locale}/messages` is the conversation list: the other party's name and avatar, what it's about, the last message preview, relative time, unread badge, and an archived filter.
  - `/{locale}/messages/{conversationId}` is the thread.
  - Both are signed-in only (sign-in redirect with the sanitised `next`), `noindex` and dynamic.
  - A non-participant gets 404, which the API already enforces.
- **Initial render is server-side.** The list and the first page of messages are fetched with `serverApi()` (1B.5b), so the thread is readable without JS and appears instantly. The client then takes over for realtime.
- **Realtime client** (`lib/chat-socket.ts`, one shared connection):
  - `socket.io-client` pinned per `minimumReleaseAge`, connecting to `NEXT_PUBLIC_API_URL` at path `/v1/socket.io` with `withCredentials: true`. The web has no bearer token, so the session cookie authenticates it.
  - `NEXT_PUBLIC_API_URL` must be in the CSP `connect-src`, which `lib/csp.ts` already does, plus `wss:` for the same origin.
  - It connects only on the messages pages and disconnects on unmount, so other pages hold no socket.
  - Events used: `conversation:join` on opening a thread, `message:send`, `typing`, `read`; incoming `message:new`, `message:deleted`, `typing`, `read`, `conversation:updated`.
  - Reconnect is Socket.IO's default backoff. On reconnect the thread refetches its first page and rejoins, because messages may have been missed. A disconnected state shows an inline "reconnecting" note and disables sending.
  - Sending falls back to `POST /v1/conversations/{id}/messages` when the socket isn't connected, since both paths share one service.
  - An error ack maps to an i18n message: 429 "slow down", 422 attachment problems, 404 for a conversation that is gone.
- **Thread behaviour.**
  - Messages are grouped by day with a date separator, and consecutive messages from the same sender are grouped.
  - Optimistic send: the message appears at once as pending, and is replaced by the server message on ack, or marked failed with a retry. Deduplicate by message id, since `message:new` also arrives for one's own message.
  - Older messages load with a "load older" button using the existing `before` cursor. No auto-scroll hijacking: the view sticks to the bottom only when the user is already at the bottom.
  - `read` is emitted when the thread is visible and focused (Page Visibility), for the newest received message, debounced 500 ms, so a background tab doesn't mark messages read.
  - Typing is emitted at most once every 2 s while typing and once on stop. The indicator shows the other party's name.
  - A deleted message renders "message deleted" and its attachments disappear, which the API already enforces.
  - Bodies are rendered as plain text, never HTML. URLs are not auto-linked in this step (that needs sanitising rules), which is recorded here so it isn't mistaken for an oversight.
- **Attachments.**
  - Upload uses the existing presigned PUT flow (1A.3): create the upload with purpose `chat_attachment`, PUT the file, complete it, then send the message with the attachment ids.
  - The picker accepts images and PDF only, up to 10 per message, with per-file progress and a clear error when the scan hasn't finished (422 from the API).
  - A message can't be sent while its uploads are still in progress.
  - Viewing calls the download endpoint for a short-lived URL on click. URLs are never put in the page's HTML, so they don't end up in caches or logs.
  - Images render as a thumbnail through the same presigned URL, not through `next/image`, because the URL is short-lived and per-viewer.
- **Unread badge.** Chat unread is separate from notifications, and paging the conversation list just to count it is wasteful, so 1B.6a adds `GET /v1/conversations/unread-count`, mirroring the notifications endpoint. The header badge reads it once per page load and then updates from `conversation:updated` while a socket exists.
- **Entry points.** The quote detail and request detail pages (1B.5b) link to the quote's conversation. The account menu gets "Messages".
- **Not in scope.** Message search, edits, reactions, read receipts per participant beyond "seen", and contact detail masking (a Phase 3 moderation increment).

## 1B.6a tasks (api-developer)

1. Contract: participant `user` summary, attachment file metadata, `subjectRef`, and `GET /v1/conversations/unread-count`. Regenerate openapi and the api-client.
2. Repository: extend the existing single-query conversation page and the message page to include these, with no N+1. The unread count is one grouped query.
3. Tests: the participant summary exposes no email, attachment metadata matches the upload, `subjectRef` for both quote paths, and the unread count matches the list.

## 1B.6b tasks (web-developer)

1. Routes and components: `messages/page.tsx`, `messages/[conversationId]/page.tsx`, `conversation-list.tsx`, `thread.tsx`, `message-bubble.tsx`, `message-composer.tsx`, `attachment-picker.tsx`, `attachment-chip.tsx`, `typing-indicator.tsx`, `connection-status.tsx`.
2. `lib/chat-socket.ts` plus a `useConversation` hook holding the merge logic (server page, socket events, optimistic sends).
3. i18n keys under `web.messages.*` in `en` only.
4. Tests:
   - the thread renders server-side without a socket;
   - an incoming `message:new` appends once and doesn't duplicate one's own message;
   - optimistic send, ack replacement and failure retry;
   - read is not emitted while the tab is hidden;
   - the typing throttle;
   - attachments: type and count limits, progress, a 422 scan error, and a click fetching a fresh URL;
   - error ack mapping;
   - the reconnect refetch;
   - a deleted message renders as deleted.
   - Web coverage thresholds must hold, and at least one test renders against the real `en` catalog.
5. Manual check against the local stack with two browser sessions (the seeded client and photographer): send both ways, attach an image, delete a message, and watch the unread badge.
