## Decisions for this step

- **Publishing before verification and payments exist.** `isPublished` requires `verificationStatus = verified` and `stripePayoutsEnabled = true` (DATA-MODEL invariant). Nothing in 1A.4 can set either, so real profiles stay unpublished until 1A.8 and 1A.9. The seed creates published, verified demo profiles directly so web and mobile can build against real data. `isPublished` is derived server-side and never accepted from clients.
- **Portfolio review before provenance exists.** New portfolio images start as `processing` and move to `pending_review` once their upload is `processed`. Only `approved` images are public. Approval arrives with 1A.10 and 1A.11; the seed inserts approved images. No auto-approval shortcut in code.
- **Slugs.** Generated from `displayName` on profile creation (ASCII-folded, lowercase, hyphenated, max 60). Suffix `-2`, `-3`… on collision. A reserved list is rejected (`admin`, `api`, `account`, `sign-in`, `sign-up`, locale codes, route segments of `apps/web`). Slugs don't change on display name edits; a slug change and redirect history are out of scope.
- **Search.** PostGIS `geography(Point, 4326)` with a GiST index. Radius search uses `ST_DWithin`, ordering by distance when lat/lng are given and by `ratingCount desc, id` otherwise. Filters: category (array contains), language, city (case-insensitive equality), price range against the lowest active tier price. Keyset cursor pagination (opaque base64 of the sort key and id). Queries are parameterised `$queryRaw` tagged templates only, never `$queryRawUnsafe`.
- **Images in responses.** URLs are built from `Upload.variants` public keys plus `S3_PUBLIC_BASE_URL` (new env, CDN or MinIO public URL in dev). Raw keys and EXIF are never returned.
- **Location privacy.** The public profile omits the exact location (already in the contract). The search response returns city only. Distance ordering must not leak coordinates through a returned distance field.

## 1A.4a tasks

1. **Contract gaps** (`packages/shared/src/contract/profiles.ts`), contract first:
   - `POST /v1/me/photographer-profile` (requires the `photographer` role, 409 if a profile exists).
   - `POST /v1/me/photographer-profile/portfolio` with `{ uploadId }` (upload must be owned, purpose `portfolio`, not deleted; 409 if already attached).
   - `avatarUploadId` and `coverUploadId` (nullable) in the update request (purposes `avatar` and `cover`).
   - Error responses for all of the above.
   - Regenerate openapi and the api-client. Add the new routes to `not-yet-implemented.ts` until 1A.4b.
2. **Schema** (schema-migrator, DATA-MODEL first):
   - `PhotographerProfile` per DATA-MODEL, with `location` `Unsupported("geography(Point, 4326)")?`, a GiST index created in the migration SQL, `categories` enum array, `languages` text array, `avatarUploadId` and `coverUploadId` referencing `Upload` (in place of raw keys), unique `slug` and `userId`, and a partial index on `isPublished` where `deletedAt` is null.
   - `PortfolioImage` referencing `uploadId` (unique) with `order`, `status` and `deletedAt`, plus width and height copied from processing.
   - `Product` with `title` localised JSON, `category`, `durationMinutes`, `deliverables` JSON, `basePriceCents`, `currency`, `isActive`, `order` and `deletedAt`.
   - `ProductTier` with `usage` (unique per product), `priceCents`, `currency`, `description` and `licenceTextVersion`.
   - `Country` reads only.
   - Update DATA-MODEL for the `*UploadId` references.
3. **Worker contract.** `image-process` records width and height on the `Upload` (add columns). Any upload linked to a portfolio image moves to `pending_review` when processed. Keep this in the worker, not the API.
4. **Seed.**
   - Three published, verified photographers in Luxembourg (Luxembourg City, Esch-sur-Alzette, Ettelbruck) with categories, languages, coordinates, and 2 products each with tiers.
   - Approved portfolio images backed by `Upload` rows marked processed, with variants pointing at placeholder objects the seed puts into MinIO. The upload step is skipped when S3 env is absent, so CI can still seed the DB.
   - Idempotent. The production guard stays in place.
5. **Tests.** Migration applies on a fresh DB. The seed runs twice without duplicates. Raw SQL `ST_DWithin` returns the expected seed profiles for a Luxembourg City radius.

## 1A.4b tasks

1. **`ProfilesModule`:**
   - `GET /v1/photographers` search (above).
   - `GET /v1/photographers/:slug`: published and not deleted only, otherwise 404 with no distinction. Portfolio shows approved images in order.
   - `GET/POST/PATCH /v1/me/photographer-profile`: owner only. PATCH validates upload ownership and purpose. Slug is immutable. `countryCode` must be an enabled `Country`.
2. **Portfolio:**
   - List all statuses for the owner.
   - Attach an upload.
   - Reorder: the id set must equal the owner's non-deleted images exactly, otherwise 422.
   - Soft delete. The public variant objects are removed by a worker job (enqueue only; the job can land with 1A.12 if not trivial, and the deferral is recorded).
3. **`ProductsModule`:**
   - Public `GET /v1/photographers/:slug/products` (active only, profile published).
   - Owner CRUD under `/v1/me/products`. Tiers are replaced as a set on update; duplicate `usage` gives 422.
   - Soft delete. A later quote referencing a product keeps working (1A.5).
   - Money only as integer cents plus currency. Currency must equal the profile country's currency.
4. **Access.** The `photographer` role is required for all `/me/photographer-profile` and `/me/products` routes (403 otherwise). OriginGuard applies on mutations. Rate limit on search per IP through the shared `RedisRateLimiter`.
5. **AuditLog.** None is required by convention (no money, verification, moderation or roles). Profile publish-state changes are logged once 1A.9 flips them.
6. **Tests** (integration against the stack):
   - search by radius, category, language and price;
   - pagination stability across pages;
   - unpublished and deleted profiles hidden;
   - non-owner and missing role;
   - upload ownership and purpose checks on attach and avatar;
   - reorder validation;
   - tier uniqueness;
   - slug collisions and reserved slugs;
   - SQL injection attempts in `city` and the cursor treated as data;
   - remove the routes from `not-yet-implemented.ts`;
   - coverage thresholds hold.
7. **Manual check:** curl the search around Luxembourg City against the seeded stack. `pnpm mock:api` still serves the regenerated contract.
